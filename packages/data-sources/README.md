# Data sources

Adapters that turn external files into domain types. This package does not serve the web UI.

`loadPinnedPassiveTreeSnapshot` reads a directory that contains `manifest.json` and `data.json`. Tests pass the development pin at `docs/data-snapshots/passive-tree`. Production must set `POE2_PASSIVE_TREE_SNAPSHOT_DIR` or pass a directory. The loader does not assume `docs/` is deployed.

`getPinnedPassiveTreeSnapshot` keeps the validated snapshot in process memory and returns the same frozen object on later calls. `refreshPassiveTreeSnapshot` writes a new pin only after schema validation and a compatible optimizer result. The refresh command supplies that result from `assessPassiveTreeRefreshCandidate`. This package does not import the passive or scoring engines. It keeps one previous generation for `rollbackPassiveTreeSnapshot`. Rollback still checks the stored snapshot files and does not re-run the compatibility gate. A running process keeps the cached object until restart.

The export's placeholder `root` node is not an allocatable passive. Class starting nodes are copied into `classStarts` from the export `classes` array and each node's `classStartIndex`. One node also links to itself. That self-link is left out of the graph and counted in the log line.

`GggCharacterProvider` is the account-character boundary. `createMockGggCharacterProvider` returns named fixture snapshots. `createDisabledGggCharacterProvider` refuses live import. `createLiveGggCharacterProvider` calls only `https://api.pathofexile.com/character/poe2` after `readGggLiveImportReadiness` is ready. That readiness needs the three GGG client variables, `GGG_CONTACT`, and `GGG_LIVE_IMPORT=enabled`. The client type is confidential. The scope is `account:characters`. Access tokens stay in memory. Refresh tokens are not stored. Unknown passive ids stay on the character and mark the import incompatible.

`importPob2Build` reads a pasted Path of Building 2 export code. The code is URL-safe Base64 around a zlib stream, then XML with root `PathOfBuilding` or `PathOfBuilding2`. Path of Building (PoE2) 0.23.1's Generate action emits `PathOfBuilding2`. It does not fetch share links. Decompression stops at 1 MiB. The XML reader does not resolve external entities. Unknown passive ids stay on the build and mark the import incompatible. Ascendancy nodes, identified from the active snapshot's ascendancy id or ascendancy-start kind, are kept off the main-tree allocation. `mainActiveSkill` selects an entry in the display-skill list from checked gem facts, not a raw gem index. Unknown skill ids stay unresolved. User configuration is read from the active `ConfigSet`'s `Input` elements. Placeholder defaults are not user configuration. A real export's `treeVersion` is kept as emitted. It is not compared with the active GGG pin version. A compatible or partial tree can enter the existing passive analysis. Skills, gear, and configuration do not change the heuristic score.

`createPoeNinjaClient` calls only the supported PoE2 economy endpoints on `https://poe.ninja`. It caches responses, sends `If-None-Match`, and retries a short bounded backoff. It does not call builds, profiles, characters, or authentication routes. Passive optimization does not use it.

`loadBuildFixture` reads a JSON build fixture and compares its passive ids with a snapshot the caller already loaded. Unknown ids and an unknown class name are reported. They are not deleted from the character. That report does not start optimization. The passive engine's readiness gate is what refuses a later path search. `fixtures/builds/` has two files mapped to the development tree pin. Skill and item names in those files are labels only.
